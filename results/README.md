# Результаты Midnight Commit

**Один час на 10 контрольных чатов включает получение, обработку, проверку и отправку в Git до стоп-кода.** Заранее подготовьте код и DEV. Команды контрольного часа: [SUBMISSION.md](../docs/SUBMISSION.md).

После оценки реальных наборов скачайте **«Результаты JSON»** в интерфейсе. Выберите DEV или PROD и сохраните файл соответственно как `results/dev/results.json` или `results/prod/results.json`.

Или подготовьте файлы из сохранённых оценок:

```sh
node scripts/prepare-results.js --split=dev --dry-run
node scripts/prepare-results.js --split=dev
node scripts/prepare-results.js --split=prod --group=CONTROL_GROUP
node scripts/check-readiness.js
```

Подготовка не делает запросов к модели. Сверка проверяет файл против исходного набора и текущих сохранённых оценок; изменение результата после апелляции делает старый файл устаревшим. Неудачная сетевая попытка сохраняется в истории и не уничтожает предыдущую готовую оценку; новый результат `needs_review` требует проверки и может попасть в сдачу как ошибка.

Проверьте файлы перед отправкой:

```sh
node scripts/validate-results.js results/dev/results.json --split=dev --source=data/datasets/DEV.json
node scripts/validate-results.js results/prod/results.json --split=prod --source=data/datasets/CONTROL_GROUP.json
```

Замените `CONTROL_GROUP` фактическим ID организаторов. Без `--source` проверяются схема и баллы; с ним дополнительно проверяются полнота ID и границы доказательств.

DEV должен содержать 65 записей, PROD — 10. Ошибки обработки сохраняются как `status: "error"`; их нельзя заменять нулём. Демо-эвристика не допускается к сдаче как модель. После проверки нужны commit и push обоих файлов до стоп-кода. Не публикуйте `.env`, исходные реальные звонки, персональные данные и подписанные API-ссылки.

`dev/results.json` пересобран после повторной обработки настоящего DEV через DeepSeek с инструкцией `2026-11-07.7`: **65 исходных ID, 65 ok, 0 error**. Он прошёл проверку с исходными диалогами. Это подтверждает формат и арифметику, но не заменяет экспертную проверку смысла оценок. Файл PROD появится после получения и обработки контрольного набора. Наличие локального файла не подтверждает его публикацию. Репозиторий не содержит вымышленных результатов, выданных за DEV/PROD.
