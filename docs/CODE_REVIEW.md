# Код-ревью и подготовка к защите · Midnight Commit

Дата: **7 ноября 2026 года**. Область: обработка ответов модели, расчёт и доказательства, кэш, апелляции, аналитика, официальный экспорт и воспроизводимость проверки. Замечания из предыдущей условной оценки жюри использованы как план улучшений; это не официальный вердикт организаторов.

## Найденные дефекты

**P1 — некорректный ответ мог влиять на голосование.** Согласие нескольких прогонов не гарантировало валидность выбранного кандидата. Ответ с повреждённым доказательством мог перевесить корректный. Теперь голосование выбирает допустимые ответы и сохраняет относящиеся к ним доказательства, причины и рекомендации. Собранный результат повторно проверяется, включая дублирующиеся объяснения. Проверки: `test/core-review.test.js`.

**P1 — апелляция могла скрыть незакрытую ошибку структуры ответа.** Подтверждение одного критерия не должно превращать весь исходно невалидный ответ модели в `ok`. Общие ошибки валидации сохраняются независимо от решения по отдельному критерию.

**P2 — стоимость неудачной обработки терялась.** Если первый ответ был оплачен, а исправляющий запрос или другой параллельный прогон падал, сведения об уже выполненной работе могли исчезнуть. Теперь все начатые прогоны завершаются до формирования ошибки; измеренные usage, стоимость, длительность и попытки сохраняются в записи неудачи. Пустой ответ с usage также учитывается. Отсутствующая информация не выдаётся за измеренный расход.

**P2 — кэш не учитывал часть конфигурации.** Лимит выходных токенов и пользовательский endpoint теперь входят в отпечаток настроек. Настройки размышления учитываются для выбранного провайдера. Снимок чек-листа создаётся до ожидания API и не меняется вместе с объектом вызывающего кода.

**P2 — неподтверждённое отсутствие грубой ошибки показывалось как «нет».** Исправлены CSV и сводка оператора: неопределённый флаг имеет отдельное значение `UNKNOWN` / «нужна проверка» и отдельный счётчик. Он не считается проверенным отрицательным ответом. Регрессии: `test/analytics.test.js`, `test/frontend.test.js`.

**P2 — повреждённый JSON мог обрушить проверку готовности.** Проверяются структуры чек-листа, источника, сохранённых оценок и файла сдачи; значения `split=constructor` / `toString` не используются как свойства прототипа. Повреждённый файл PROD получает статус блокировки, сохраняя доступность остальной сводки. Регрессии: `test/export.test.js`, `test/submission.test.js`.

**P2 — сообщения провайдера могли содержать секреты.** Перед журналированием и возвратом ошибки удаляются настроенные ключи, Bearer, общие поля авторизации и подписи URL. Повреждённый HTTP JSON не повторяется как временная сетевая ошибка. Это снижает риск лишних платных повторов и раскрытия ключа.

**P2 — снижение c06 могло повторять штраф другого критерия.** Контрольный прогон обнаружил, что отсутствие решения или плохое завершение повторно снижает «Качество общения». В инструкции `.7` требуется отдельное наблюдаемое нарушение ясности, последовательности, порядка диалога или ожидания. Определение и шкала чек-листа не изменены, ответы и баллы конкретных примеров в промпт не зашиты. Одно расхождение EN/c06 остаётся открытым.

## Что добавлено по замечаниям жюри

- **Измеримая проверка RU/KZ/EN:** 15 синтетических инженерных примеров, 120 заранее заданных ответов. Отчёт содержит фактические ответы и доказательства, совпадения по языкам/критериям, critical и N/A confusion, ошибку итогового балла, время, наблюдаемый расход, а также неудачные и невалидные случаи в знаменателях.
- **Проверка готовности в интерфейсе:** результаты контрольного прогона, состояние файлов DEV/PROD, скачивание полного отчёта и сценария защиты. Блок доступен даже без оценок по выбранному чек-листу. Ошибка загрузки имеет ручной повтор.
- **Подготовка файлов сдачи:** `prepare:results` сохраняет официальный JSON в установленные пути; `check:readiness` сверяет исходные ID, текущие результаты и наличие контрольного набора. После изменения оценки старый файл становится устаревшим. Error-записи сохраняются, демо-эвристика блокируется.
- **Воспроизводимый запуск набора:** `evaluate:dataset` по умолчанию показывает план без API. Выполнение требует `--live`; действуют лимит новых оценок, максимум два параллельных диалога и сохранение истории. Спорный текущий результат не перезапускается без отдельного флага.
- **Сценарий защиты:** четыре блока на 300 секунд — интерфейс, оценка с доказательствами и звонком, апелляция, замена критерия на копии чек-листа. Примеры апелляций используются только на синтетических данных.
- **CI:** добавлен GitHub Actions для Windows и Ubuntu / Node.js 24 с локальными тестами без ключей и платных вызовов. Удалённый workflow в этой сессии не запускался.

Команды локальной проверки:

```sh
npm run check
npm test
npm run benchmark
node scripts/validate-results.js results/dev/results.json --split=dev --source=data/datasets/DEV.json

git diff --check
```

`npm test` использует изолированные временные хранилища и имитацию API, без платных обращений и изменения реального DEV. Проверки DOM — программные регрессии, не браузерный рендерер. `check:readiness` намеренно возвращает 1, пока PROD отсутствует или другая проверка не завершена.

## Открытые ограничения

1. Нужны независимая экспертная разметка и отдельный контрольный набор. В инженерном наборе мало critical-положительных случаев; не покрыты промежуточные ступени c04, c06=0, консультация N/A и качество голоса.
2. Полная браузерная и мобильная приёмка, прослушивание и перемотка звонка, клавиатура, печать и реальная репетиция за пять минут не подтверждены. В этой сессии инструмент сообщил: `The browser access host is unavailable`; нативный канал также недоступен.
3. PROD организаторов ещё не получен; результат на вымышленных данных вместо него не создаётся. Commit и push файлов не выполнялись.
4. JSON-хранилище и очередь рассчитаны на один локальный сервер. Для публичного сервиса нужны авторизация, постоянная очередь и БД.

Для применения нового backend в терминале работающего сервера нажмите **Ctrl+C**, затем `node server.js`; в браузере — **Ctrl+F5**. Второй сервер на занятом порту 3000 запускать не нужно.
