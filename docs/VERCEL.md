# Развёртывание CQA на Vercel

Production: **https://midnight-commit-cqa.vercel.app**, проект `lowqrsts-projects/midnight-commit-cqa`. Опубликован через Vercel CLI 8 ноября 2026 года. Состояние команды хранится в подключённом Neon **Free (`free_v3`)**; платный тариф не подключался. Доступ закрыт логином и паролем команды.

Логин по умолчанию — `midnight`. Локальный пароль находится в `.vercel/access.local.json`; файл исключён из Git и загрузки. Ключ DeepSeek, пароль и адрес API данных сохранены только в серверных Secrets production. Их значения не включены в публичный репозиторий.

Облачная версия использует Node.js Function и постоянный Postgres. Локальный запуск сохраняет JSON-хранилище. `/tmp` не используется как база данных; локальные `data/`, `.env` и ключи не входят в загрузку. Правила загрузки задаёт `.vercelignore`.

## Подключение проекта

1. Подключите аккаунт Vercel к чату либо авторизуйте официальный Vercel CLI. Доступ к аккаунту необходим для создания проекта, переменных и публикации.
2. Выберите проект и подключите Postgres через Vercel Marketplace, например Neon. Учитывайте тариф выбранного провайдера; наличие конфигурации не означает созданную базу.
3. В Environment Variables нужной среды задайте серверные настройки ниже. Не помещайте секреты в `vercel.json`, клиентский JavaScript или Git.
4. Опубликуйте каталог проекта. Vercel устанавливает зависимости из `package-lock.json` и выполняет `npm run build`: строгую проверку TypeScript и сборку React через Vite в `dist/`. Конфигурация `framework: null` использует `api/index.js`, куда включается собранный интерфейс. Минимальная версия Node.js — 22.12; фактическую версию среды смотрите в журнале деплоя.

Необходимые настройки:

- `CQA_STORAGE_DRIVER=postgres` — постоянное хранилище; на Vercel облачный режим также определяется автоматически.
- `CQA_DATABASE_URL` — строка подключения Postgres. Допускаются предоставленные интеграцией `DATABASE_URL` или `POSTGRES_URL`.
- `CQA_WORKSPACE_ID=midnight-commit` — отдельное пространство команды; preview лучше подключать к отдельной базе или workspace.
- `CQA_ACCESS_USERNAME=midnight` — имя пользователя для входа; `midnight` используется по умолчанию.
- `CQA_ACCESS_PASSWORD` — уникальный пароль доступа к приложению, минимум 16 символов.
- `LLM_PROVIDER=deepseek`, `LLM_MODEL=deepseek-flash`, `DEEPSEEK_API_KEY` — реальная модель и ключ только на сервере.
- `DATA_API_URL` — выданный организаторами адрес API данных. Если он содержит токен доступа, храните полный адрес только в серверной переменной.

Для небольшой демонстрации начните с `SAMPLES=1`, `LLM_TIMEOUT_MS=45000`, `LLM_MAX_ATTEMPTS=1`, `REPAIR_ATTEMPTS=1`. Облачная конфигурация ограничивает один HTTP-запрос модели 60 секундами, убирает сетевые повторы и допускает максимум один запрос исправления ответа. Один запрос функции ограничен 180 секундами. Ошибка модели сохраняется как ошибка обработки, а не как выдуманный балл. Настройки времени — предел ожидания, а не гарантия успешного ответа.

## Как работает облачная версия

Все URL, включая HTML и ассеты React из `dist/`, направляются через общий обработчик с проверкой доступа. В конфигурации используется единственный catch-all маршрут без `handle: filesystem`. Исходники `web/`, конфигурация Vite и брендовые ассеты `public/` входят в загрузку для сборки; `.env`, исходные диалоги и локальные настройки исключены. Vite не читает корневой `.env` и не включает серверные ключи в клиентский пакет.

Клиентские модули Vite выпускаются с расширением `.mjs`, сервер отдаёт их с MIME `text/javascript`. Это сохраняет браузерный ESM-код при включении в пакет Node.js Function: включённые `.js` сборщик Vercel преобразовывал в CommonJS. После публикации проверяйте HTTP-ответы HTML, основного модуля и модулей страниц, сравнивайте их с локальной сборкой; одного успешного статуса деплоя недостаточно.

Состояние команды хранится в Postgres. Изменения одной команды выполняются последовательно и фиксируются до отправки успешного HTTP-ответа. Это вариант для небольшого MVP: длительная оценка может задержать другую операцию изменения, включая отмену.

Пакетное задание и его прогресс сохраняются в базе. Интерфейс отправляет отдельные шаги оценки, каждый обрабатывает один диалог. Держите вкладку открытой до окончания; закрытая вкладка приостанавливает выполнение. После смены экземпляра функции сохраняются уже зафиксированные оценки и прогресс. Незавершённая из-за прерывания функции транзакция не считается успешной; счёт за уже отправленный модели запрос при этом возможен.

Локальные наборы и история автоматически в облако не копируются. После настройки закрытого приложения импортируйте разрешённые исходные данные через его API/интерфейс. Официальный DEV JSON включается в серверный пакет для сверки готовности, но не заменяет исходные транскрипты и сохранённые оценки в базе.

## Перенос сохранённых наборов и истории

Предварительная проверка не использует сеть и не читает пароль:

```sh
npm run migrate:workspace
```

С согласия пользователя перенесены текущие локальные данные: 3 набора, 1 чек-лист, 135 оценок с вложенными апелляциями — 139 записей, 5 пакетов, около 4,28 МБ. Исходные данные и история сохранены в закрытом облачном пространстве.

Для переноса используются логин и пароль из локального `.vercel/access.local.json` с полями `username` и `password`. Каталог исключён из Git и загрузки. Передача допускается только на точный HTTPS-адрес; перенаправления не выполняются.

```sh
node scripts/migrate-workspace.js --live --url=https://YOUR-PROJECT.vercel.app --auth-file=.vercel/access.local.json
```

Совпадающие записи пропускаются; отличающиеся существующие записи дают конфликт. Для первого переноса в новое пустое пространство нужен `--replace-existing`: он заменит начальный облачный чек-лист его локальной копией. Перед применением этого флага к существующему рабочему пространству проверьте, какие данные заменяются. Отправка идёт последовательными пакетами меньше 1 МиБ, без вызовов модели. `.env`, ключи и незавершённые фоновые задания не переносятся.

Хранилище использует PostgreSQL `json`, сохраняя исходный порядок полей. Это требуется для совместимости ранее сохранённых хешей транскрипта и ключей кэша. Старый `jsonb` автоматически преобразуется без удаления данных; явный повтор импорта с `--replace-existing` восстанавливает исходный порядок полей записей. Повтор идентичного восстановления пропускается.

Облачный сайт не делает commit/push в Git. Для сдачи скачайте **«Результаты JSON»** из облачного списка диалогов, сохраните их в локальные `results/dev/results.json` и `results/prod/results.json`, проверьте и отправьте по [SUBMISSION.md](SUBMISSION.md). Локальная команда подготовки использует локальное хранилище, поэтому изменения облачных оценок нужно выгрузить отдельно.

Автоматическая привязка к GitHub не настроена; публикация выполнена непосредственно из каталога через CLI. Пока GitHub не подключён в настройках Vercel, новые изменения публикуются командой `npx vercel deploy --prod --scope lowqrsts-projects`.

Проверьте: запрос без пароля отклонён; вход открывает сайт; новая запись и апелляция сохраняются после повторного обращения; пакетная оценка проходит через несколько шагов; JSON-экспорт имеет исходные ID. Проверяйте модель сначала на синтетическом примере и учитывайте платные API-вызовы.

Не объявляйте развёртывание завершённым только по успешной локальной проверке. Нужны готовый статус Vercel и проверка фактического HTTPS URL. Изменение Environment Variables требует нового деплоя.
