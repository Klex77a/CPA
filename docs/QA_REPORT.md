# QA-проверка CQA · Midnight Commit

Это отчёт предыдущего QA-прогона. Последующие исправления, контрольные прогоны RU/KZ/EN и согласованная повторная обработка DEV описаны в [CODE_REVIEW.md](CODE_REVIEW.md).

Дата: **7 ноября 2026 года**. Проверена рабочая версия проекта и сайт `http://127.0.0.1:3000`. Исправления ниже находятся в рабочем дереве. Основной процесс пользователя не перезапускался: для применения серверных изменений нужен перезапуск в его терминале, затем обновление страницы.

## Результат

Основные проверенные API-сценарии работают. Найдены и исправлены ошибки конкурентных изменений, актуальности оценок, неизвестных флагов, восстановления очереди и аналитики. После исправлений проходят **14 наборов тестов** и проверка синтаксиса **30 JavaScript-файлов**.

Это не полный визуальный sign-off: управление Chrome было остановлено инструментом из-за невозможности достоверно определить текущий URL. Браузерный рендер, мобильный экран, реальное перемещение фокуса/скринридер, печать и воспроизведение аудио не отмечены как пройденные.

## Проверено на работающем сайте

- Сайт и API конфигурации отвечают; провайдер — DeepSeek, модель — `deepseek-flash`.
- В текущем DEV **65 сохранённых оценок**, все со статусом `ok`.
- Официальный DEV JSON возвращается HTTP 200, содержит **65 ok / 0 error**, исходные ID сохранены. Независимый валидатор с исходным DEV подтвердил схему, все восемь кодов, типы, ступени, границы реплик и арифметику без ошибок.
- Сервер успешно разрешил ссылки на **все 5 записей** DEV: HTTP 302. Аудиофайлы целиком не скачивались; прослушивание/перемотка в браузере этим не подтверждены.
- Повторная оценка реального DEV в ходе QA не запускалась. Проверка его экспорта не доказывает смысловую правильность всех 65 модельных оценок.

## Один настоящий запрос к модели

Для проверки подключения использован только синтетический RU-пример в отдельной группе `QA_20261107`. Реальные транскрипты звонков в новом запросе к модели не передавались.

- Один POST оценки и один фактический HTTP-запрос к DeepSeek, без повторной платной обработки набора.
- Длительность **9,46 с**, приблизительная стоимость по usage/настройкам **$0,003003**.
- Все **8 критериев** валидны, `validation_errors=[]`; ID доказательств и причины N/A проверены.
- Исходный итог **100** совпал с независимым расчётом: набрано 85 / применимый вес 85.
- Подтверждение апелляции, изменение c04 со ступени 20 на 15, обязательная причина, запрет повторного решения и недопустимой ступени 11 проверены. Исходные 100 сохранены, тестовый финал — **94,12**.
- Список, аналитика и очередь апелляций показывают согласованный результат; пройдены 16 проверок API.
- Ответы восьми критериев сверены с содержанием этого RU-примера. Четыре непроверяемых утверждения консультации помечены для проверки человеком; фактическая правильность тарифов/сроков не объявлена установленной.

Замечание P3: один необязательный совет модели повторяет уже присутствующее в диалоге предупреждение о банке-получателе. Балл от этого не изменён. Это наблюдение о качестве рекомендаций, а не подтверждение смысловой точности на всех языках. Новые живые KZ/EN-прогоны в этом QA не выполнялись.

## Найденные дефекты и исправления

| ID | Важность | Воспроизведение / прежнее поведение | Исправление и проверка |
|---|---|---|---|
| QA-01 | P1 | Два отложенных POST апелляций разных критериев: оба 201, в хранилище оставалась одна. Решения могли теряться аналогично | После чтения тела запроса повторно читается последняя оценка, затем синхронно проверяется/сохраняется изменение. Настоящие chunked HTTP-регрессии сохраняют обе апелляции и решения |
| QA-02 | P1 | Одновременные сохранения чек-листа читали одну старую версию до await | Последняя версия читается после тела запроса. Получаются последовательные версии 2 и 3 с полной историей |
| QA-03 | P1 | Повторный импорт изменённого текста под тем же ID оставлял старые баллы текущими; прежние индексы доказательств указывали на новые сообщения | Добавлены freshness-поля и независимый snapshot исходной записи. Устаревший результат не входит в текущие список/аналитику/CSV/JSON. История остаётся доступной; архив использует сохранённый текст, а без snapshot переходы к старым доказательствам отключены |
| QA-04 | P1 | `c08=INVALID` при `gross_error=false` показывался как «Грубых ошибок нет» | Отдельный признак неизвестного флага в API, карточке, списке и аналитике. Непроверенное отсутствие не считается подтверждённым |
| QA-05 | P2 | Один 503 при опросе пакетной задачи останавливал polling навсегда, кнопка оставалась заблокированной | Автоматическое восстановление с задержкой до 10 с, ручной повтор без дублирующихся запросов; 404 после перезапуска освобождает кнопку и объясняет ситуацию |
| QA-06 | P2 | Медиана для 60 и 100 равнялась 60 | Для чётного числа оценок берётся среднее двух центральных: **80** |
| QA-07 | P2 | Все `!scored` считались N/A, включая INVALID и нулевой вес | N/A считается только для ответа NA; INVALID выделен отдельно, нулевой вес не превращается в неприменимость |
| QA-08 | P1 | Локальный API принимал посторонний Host с совпадающим Origin | При локальной привязке разрешены только localhost/loopback-имена; запрос с посторонним Host получает 421. Проверено сырым HTTP-запросом, без внешнего DNS/сети |
| QA-09 | P1 | Явный `conversation_ids: []` запускал весь набор вместо пустого выбора, что могло вызвать неожиданные платные запросы | Пустой/повреждённый список, неизвестные и повторяющиеся ID отклоняются 400 до запуска модели. Корректный subset обрабатывает ровно выбранный диалог |
| QA-10 | P2 | Пробельный group_id сохранялся как пустой; отмена отсутствующей задачи возвращала успешный ответ | Валидация 400 для пробельной группы; 404 для отсутствующей задачи |
| QA-11 | P2 | Кэш доказательств апелляций использовал склейку группы и ID через `/`, допускающую совпадение разных пар | Ключ теперь кодирует пару через JSON.stringify, без смешивания транскриптов |

Новые snapshot сохраняются до ожидания модели. Старые оценки без snapshot не получают выдуманный исходный текст. Для архива с изменённым источником встроенный плеер текущей записи выключен; доступна исходная ссылка из snapshot, если она сохранилась. Изменение языка/канала при том же тексте также не позволяет использовать старую оценку как актуальную.

## Воспроизводимые проверки

```sh
npm run check
npm test
node scripts/validate-results.js tmp/qa-dev-export.json --split=dev --source=data/datasets/DEV.json
git diff --check
```

В PowerShell при блокировке npm.ps1 используйте `npm.cmd`. Все 14 наборов `npm test` работают без настоящих платных запросов и без изменения реального DEV. Покрытие: scoring, validation, pipeline, DeepSeek adapter, results, hardening, export, audio-access, evaluation-failure, appeals-concurrency, freshness, analytics, frontend, batch-selection.

Frontend regression — обычный software-тест с минимальным DOM test double. Он проверяет неизвестный/проверенный critical, устаревшие список и карточку, архивный snapshot, запрет перехода к недоступному исходнику, восстановление после 503/404, backoff и отсутствие параллельных повторов. Он не является браузерным рендерером.

Отдельный прежний smoke также прошёл: **28 подменённых запросов**, старт, sample/import, форма Midnight Commit, обработка 422 при JSON-экспорте, скачивание с предупреждением об error-записях, черновик чек-листа, отмена modal и восстановление inert.

Локальные подробности сохранены в ignored `tmp/`: `qa-tests.log`, `qa-live-report.json`, `qa-audio-report.json`, `qa-dev-export.json`, `qa-backend-report.txt`, `qa-frontend-report.txt`. JSON DEV сохранён там как проверочная копия, а не автоматически опубликованный файл сдачи. Исходные реальные данные и секреты не добавлялись в Git.

## Что нужно проверить вручную

1. В терминале действующего сервера: Ctrl+C, затем `node server.js`. Не запускайте второй сервер поверх занятого порта 3000.
2. Обновить страницу с очисткой кэша: Ctrl+F5.
3. Открыть карточку DEV, перейти к реплике-доказательству, проверить длинный текст, фильтры и клавиатуру.
4. Прослушать реальный звонок и сравнить перемотку с репликой; позиции приблизительные.
5. Пройти апелляцию и изменение чек-листа через браузер; проверить узкий экран и печать.

После этих проверок можно закрывать визуальную приёмку. В рамках этой задачи сервер пользователя не останавливался, реальные DEV-оценки не перезаписывались, результаты не публиковались и push не выполнялся.
