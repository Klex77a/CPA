# Независимая ручная проверка качества

Подготовлен инструмент слепой разметки. Проверка человеком пока **не выполнена**: нет завершённых экспертных ответов и нет доказанной точности на независимом наборе. Новый challenge из 39 синтетических случаев — инженерная проверка; он не заменяет экспертов и скрытый набор организаторов.

## Подготовка приватного пакета

Команды выполняются в локальном репозитории. Сначала проверьте план — без записи и запросов к модели:

```sh
node scripts/review-quality.js prepare --source data/datasets/DEV.json --count 30
```

Для создания пакета:

```sh
node scripts/review-quality.js prepare --source data/datasets/DEV.json --count 30 --seed midnight-review-v1 --out output/private/human-dev-v1 --write
```

Получатся `packet.json` и `source-map.private.json`. Отбор не использует оценки модели: балансируются языки, в выборку сначала включаются доступные звонки. Для текущего DEV выборка из 30 содержит по 10 RU/KZ/EN и все пять звонков. Пакет содержит исходные тексты, поэтому в нём могут оставаться персональные данные. Замена ID на случайные не означает обезличивания содержания.

Не публикуйте пакет, соответствие ID и экспертные ответы в Git или Vercel. Запись CLI разрешена только внутри исключённой папки `output/private/`; существующие файлы, символические ссылки и junction не перезаписываются. CLI не обращается к провайдеру и не меняет DEV-оценки или результаты сдачи.

## Разметка двумя экспертами

1. Передайте **один и тот же** `packet.json` двум экспертам, имеющим право работать с этими диалогами. Не передавайте ответы модели и `source-map.private.json`.
2. На сайте откройте **«Проверка качества» → «Открыть пакет»**. JSON обрабатывается в браузере; эта страница не отправляет его на сервер.
3. Каждый эксперт независимо выбирает ответ по каждому критерию, пишет основание и отмечает реплики. Для пропущенного действия указывает проверенный участок. N/A означает неприменимость, а «Не могу проверить» — недостаточность фактов или знаний; эти состояния различаются в файле и метриках.
4. Перед закрытием вкладки скачайте черновик. Для продолжения снова откройте пакет и нажмите **«Загрузить черновик»**. Ответы не сохраняются автоматически на сервере.
5. Укажите ID эксперта и квалификацию, подтвердите личную проверку без ответов модели и помощи ИИ. **«Сдать разметку JSON»** скачивает файл со статусом `submitted`; незаполненный черновик эталоном не считается.

Идентичность и независимость проверяющего подтверждаются его заявлением. SHA-256 связывает файлы с неизменённым пакетом, но не удостоверяет личность автора и не доказывает независимость. Интерфейс и отчёт не выставляют `independent_expert_validation=true` автоматически.

## Согласование разногласий

Сохраните скачанные файлы как `reviewer-a.json` и `reviewer-b.json` внутри приватной папки. Сверка без записи:

```sh
node scripts/review-quality.js reconcile --packet output/private/human-dev-v1/packet.json --left output/private/human-dev-v1/reviewer-a.json --right output/private/human-dev-v1/reviewer-b.json
```

Добавьте `--out output/private/human-dev-v1/consensus.json --write`, чтобы сохранить результат. Код завершения 1 означает оставшиеся разногласия. Рядом создаётся `consensus.resolutions-template.json`; он содержит только спорные критерии. Третий эксперт заполняет решения, обоснования, реплики и свои сведения/подтверждения. Его ID должен отличаться от двух первоначальных проверяющих. Повторите команду с `--resolutions output/private/human-dev-v1/consensus.resolutions-template.json` и новым `--out output/private/human-dev-v1/adjudicated.json --write`.

Не меняйте исходные экспертные файлы после подготовки решений: adjudication привязан к их контрольным суммам. Согласованный UNKNOWN остаётся UNKNOWN и снижает полноту разметки.

## Сравнение с моделью

```sh
node scripts/review-quality.js compare --packet output/private/human-dev-v1/packet.json --manifest output/private/human-dev-v1/source-map.private.json --reference output/private/human-dev-v1/adjudicated.json --evaluations data/evaluations --out output/private/human-dev-v1/comparison.json --write
```

Если разногласий не было, используйте `consensus.json`. Сравниваются исходные ответы модели **до апелляций**, с совпадающими источником и чек-листом. Демо-результаты, неизвестная модель, недопустимый ответ и ошибочные доказательства не засчитываются как верные предсказания. Пропуски модели остаются в знаменателе; человеческий UNKNOWN исключается с явным показом покрытия. Отчёт содержит точность по размеченным критериям, MAE по полностью проверенным диалогам, critical и N/A precision/recall. Разные модели и версии промпта нужно сравнивать отдельно.

DEV уже использовался при разработке. Независимая человеческая разметка DEV полезна, но не превращает этот набор в ранее не виденный holdout. Для честной проверки обобщения нужны новые заранее отложенные диалоги и замороженные до запуска модели человеческие ответы.
